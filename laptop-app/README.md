# Laptop app — Bindrune

Static kiosk application. No dependencies, no build step, no framework: plain
HTML, CSS and classic scripts so it also runs straight from `file://` on a
museum laptop.

```bash
python -m http.server 5180 --directory laptop-app   # http://localhost:5180
```

To also get the **Bindrune intro** (Jörmungandr circling the globe, shared with `rune-vision/globe/intro.js`),
serve the repository root instead, so the app can reach that folder:

```bash
python -m http.server 5180   # run in the repository root, then open http://localhost:5180/laptop-app/
```

Click, Space or Esc skips the intro. Without it (file://, or the first command) the app starts directly.

## Structure

| file | role |
| --- | --- |
| `index.html` | Kiosk shell: masthead, map panel, board rail, reveal mount. |
| `css/style.css` | All styling, including the reveal animation and reduced-motion fallbacks. |
| `js/data.js` | Runes, kennings, seats, NFC tag UIDs, map label placement. |
| `js/puzzle.js` | State machine: NFC verification → beacon → mesh links → reveal. |
| `js/map.js` | Parchment world chart, sea-monster easter eggs, rune markers, mesh beams. |
| `js/board.js` | Seats, stone tray (drag or click), reader chronicle. |
| `js/reveal.js` | Builds and swims Jörmungandr around the map: body, head, dives, splashes. |
| `js/bridge.js` | Optional Web Serial bridge for the physical gateway. |
| `js/app.js` | Wiring, keyboard shortcuts, serial event handling. |
| `js/world-map.js` | Generated SVG geometry — do not edit by hand. |
| `js/runes.js` | Hand-drawn Elder Futhark glyph paths. |

## How the state machine behaves

`placeRune(runeId, seatIndex)` puts the stone on the seat and starts a simulated
reader cycle:

- **scan** (950 ms) — tag read, then accepted or rejected against the seat.
- **activate** (800 ms) — accepted stone starts broadcasting; it appears on the map.
- **link** (750 ms per peer) — each pair of broadcasting stones links with a
  signal strength, then the beam is drawn.
- When all three stones have two peers the state becomes `ready`: the map
  offers **Awaken the serpent** and waits. Nothing is automatic; the finale only
  starts when a visitor presses the button, which calls `awaken()`.

A refused stone returns to the tray and the seat flashes an ember red. `reset()`
clears pending timers, the map, and the chronicle.

Timings for the reader cycle live in `TIMING` at the top of `js/puzzle.js`. The
finale is driven frame by frame in `js/reveal.js`; its pace is `LEAD` (breath
before the breach) and `TRAVEL` (milliseconds to swim the world).

## Hardware mode

`Connect reader` asks for a Web Serial port at 115200 baud and parses one JSON
object per line. A `scan` event is authoritative: it seats the stone exactly as
a click would. Outgoing `activate` and `reset` messages are sent for the
gateway. Unknown tag UIDs are logged, not guessed — add them to `data.js`.

Web Serial needs Chrome or Edge and a secure context (`localhost` is fine,
`file://` is not). Anything else keeps working in simulation.

## Map data

`js/world-map.js` is generated by `tools/build_map.py` from Natural Earth 1:110m
(public domain). Land, borders, the monster sketches and the serpent route are
pre-projected with a Miller cylindrical projection and fitted to a 1600×900
viewBox, so the browser only ever draws path strings. The projection is periodic
in longitude at the full map width, which is what lets the serpent's route close
on itself exactly after 360°. Antarctica is intentionally omitted: the
installation's world is the Norse one. Rerun the tool after changing `SITES`,
`MONSTERS` or `SERPENT_ROUTE`.

## Notes

- Fonts (Cinzel, EB Garamond) load from Google Fonts and fall back to Georgia
  when the laptop is offline.
- The layout targets a 16:9 kiosk at 1600×900 or larger; below 1120 px wide
  (or 720 px tall) it stacks and scrolls for development.
- `F` toggles fullscreen, `R` resets, `Esc` resets from the finale, for
  unattended use.
- Respects `prefers-reduced-motion`: the finale appears fully drawn, without the
  journey, instead of animating.
